
# P1 - Requirements Classification

## Project: Doctor Appointment Booking System

### Functional Requirements

Functional requirements describe what the system must do.

| ID | Requirement |
|---|---|
| R1 | A patient can view the days and times when a doctor is available. |
| R2 | A patient can book an appointment during an available time slot. |
| R3 | A doctor can accept or decline an appointment request. |
| R4 | A patient can have at most N upcoming appointments at any given time. |

### Non-Functional Requirements

Non-functional requirements describe quality attributes and constraints of the system.

| ID | Requirement | Category |
|---|---|---|
| R5 | Patient medical data shall be accessible only to authorized staff. | Security |
| R6 | Available appointment times shall be displayed within 2 seconds. | Performance |
| R7 | The application shall be usable on mobile phone screens. | Usability |

### Project Constraint

N = 3

Each patient can have a maximum of 3 upcoming appointments.

### Summary

- Functional Requirements: R1, R2, R3, R4
- Non-Functional Requirements: R5, R6, R7
- Total Requirements: 7
